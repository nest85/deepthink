# DeepThink(帮你深度思考复杂问题)

## 这个 skill 是干什么的

帮用户分析复杂问题。区别于直接套一个分析框架,本工具:

1. **识别问题类型**(理解/决策/预测/机会/诊断/设计/比较)
2. **动态选择**最合适的若干个方法论
3. **解释为什么选**(让用户在过程中学到方法论本身)
4. **逐个执行**每个方法论,并显式标记分析过程
5. **综合输出**:不仅给结论,还高亮方法论之间的分歧——分歧往往指向真正的不确定性
6. **询问是否生成文件**:综合完成后,询问用户是否保存为 .md / .html / 两者 / 不需要,按需生成

## 核心原则

- **分歧是信号,不是噪音**:当两个方法论给出相反结论,要保留分歧并说明原因,不强行调和
- **解释选择**:为什么选 A 不选 B,显式说出来——这是教学层
- **拒绝硬套**:不是所有问题都需要方法论分析(见"拒绝判断")

## 执行流程

### 第 0 步:输入判断

接到用户问题后,先判断是否属于以下"不适用"情况。如果是,直接告诉用户"这个问题不需要方法论分析"+给出更合适的处理方式,然后停止:

**拒绝判断(不适用场景)**:
- 纯事实查询:"北京到上海多远"、"X 公司什么时候成立"
- 纯创作请求:"帮我写首诗"、"画一张海报"
- 纯执行指令:"把这段代码改成 Python"、"翻译这段话"
- 信息明显不足以分析:"我应该怎么办"(没有任何上下文)→ 先问清楚再判断

### 第 1 步:检查用户是否指定方法论

如果用户明确说了"用 X 方法论分析"(比如"用第一性原理+对立面分析这个问题"),**跳过第 2、3 步**,直接从第 5 步开始,只用用户指定的方法论。

### 第 2 步:问题分类

把问题归类为下面 7 种之一(可以同时是多种,识别 primary + secondary):

| 问题类型 | 典型句式 | 核心问的是 |
|---|---|---|
| **理解类** | 为什么...、...的本质、怎么看... | 现象背后的机制 |
| **决策类** | 我应不应该...、要不要... | 在选项之间选择 |
| **预测类** | ...会怎么发展、未来... | 未来走向 |
| **机会类** | 这里有什么机会、空隙在哪 | 未被满足的需求 |
| **诊断类** | 为什么坏了、哪里出问题 | 找出根因 |
| **设计类** | 怎么做出...、怎么搭一个... | 构造方案 |
| **比较类** | A 还是 B、X 和 Y 哪个 | 在已知选项里选 |

如果问题信息不足以分类,问 1-2 个澄清问题(精炼,不啰嗦)。

### 第 3 步:选择方法论

读 `methodologies/` 下相关文件,基于以下规则选:

**问题类型 → 方法论映射(参考,不是死规则)**:

| 问题类型 | 优先方法论 |
|---|---|
| 理解类 | 第一性原理 + 系统思维 + 对立面 |
| 决策类 | Pre-mortem + 可逆性判断 + 机会成本 + 二阶思维 |
| 预测类 | 二阶思维 + 系统思维 + 对立面 |
| 机会类 | 利益结构 + JTBD + 对立面 + 第一性原理 |
| 诊断类 | 5 Whys + 系统思维 + 利益结构 |
| 设计类 | 第一性原理 + Pre-mortem + 对立面 |
| 比较类 | 机会成本 + Pre-mortem + 二阶思维 |

**冗余规避(同时选会浪费)**:
- 5 Whys ≈ 第一性原理(都挖根因,前者粒度浅)——只选一个
- 二阶思维 ≈ 系统思维(都看动态,后者更全面)——可以同选但侧重不同
- 对立面 ≈ Pre-mortem(都问"哪里出错",后者更具体)——通常选一个

**数量原则**:
- 简单问题:2 个
- 中等问题:3-4 个
- 复杂问题:5-7 个
- 标准是"信息边际价值":再加一个方法论如果只重复已有结论,就不加

### 第 4 步:CHECKPOINT 1(必须停顿)

向用户呈现:

```
我判断这是【X 类(primary) + Y 类(secondary)】问题。
准备用这几个方法论:
- 方法论 A:[1 句话说为什么这里用得上]
- 方法论 B:[同上]
- 方法论 C:[同上]
共 N 个。可以开始吗?或者你想换/加/减?
```

等用户确认/调整后再继续。

### 第 5 步:逐个执行方法论

对选中的每个方法论:

0. **【先识别事实】**动笔前列出本方法论需要的关键事实(具体数字、时间点、政策、市场规模、竞品行为等):
   - 任何"当前/最新/现在/今年"相关的事实 → **必须 web_search**,不能凭记忆
   - 训练截止(2026-01)前的稳定事实 → 可用训练数据,但要标注大致时间
   - 实在查不到的 → 明说"无可靠数据,以下为推断",不要假装有依据

1. 读 `methodologies/<方法论名>.md` 获取具体执行步骤、输出模板、质量自检条款
2. 严格按文件中的"执行步骤"展开,不省略
3. **每个具体事实在文中用来源标签标注**:
   - `[搜索]` — 刚通过 web_search 查到
   - `[训练:截至 2025-XX]` — Claude 训练数据里的稳定事实(标大致时间)
   - `[推断]` — 无事实支撑,基于其他事实推导得出的判断
4. 在文件中的"质量自检"提示下自我审一遍输出,若发现停留在表面,继续挖
5. 输出该方法论的分析结果(在最终文档里这部分会有 1-2 句方法论简介,作为教学层)
6. **方法论末尾追加"【本节事实清单】"小节**:列出本节用到的所有数字/时间/事件 + 来源标签 + (如果是搜索)简短出处

### 第 6 步:CHECKPOINT 2(全部方法论执行完后,必停)

跑完所有方法论后、综合前,做信息完整性检查:

1. **回顾每个方法论的输出**,识别"因为信息不足而结论模糊"的部分
2. **如果有信息缺口**,告诉用户:
   - 哪些方法论需要补充信息
   - 具体需要补充什么(列出具体问题,不要泛泛说"需要更多信息")
3. 用户回复后,问用户选择:
   - "全部方法论重新执行"
   - "只重新执行 [方法论 X、Y]"
4. **如果没有信息缺口**,直接进入第 7 步(综合)

### 第 7 步:综合(Synthesis)→ 输出到对话

读 `synthesis.md` 并执行其中的四步综合程序:
1. 收敛结论(所有方法论指向同一方向的部分)
2. 分歧结论(方法论之间打架的地方,及打架的原因)
3. 主导约束(系统里最硬的瓶颈/最关键的变量)
4. 行动建议 + 置信度依据

**重要**:综合结果**直接在对话里输出**,不要生成文件——是否生成文件由第 8 步用户决定。

### 第 8 步:询问用户是否保存文件

综合输出完后,问用户:

```
分析完成,是否要保存为文件?
- md(纯文本,便于编辑/复制)
- html(可视化,便于阅读/分享)
- 两个都要
- 不需要(流程结束)
```

根据用户选择:

**如果用户选 md / html / 两者**:

1. 用 `output-templates/analysis.md` 和/或 `output-templates/analysis.html` 作为模板,填充完整内容,生成文件

2. **文件命名规则**:
   - 文件名 = 对"分析问题"的一句话总结(20 字以内)
   - 中文,去掉所有标点符号
   - 必须抽象问题的核心主题,而不是重复原问题
   - 示例:用户问"AI Agent 是否会替代 SaaS",文件名 → `AI Agent替代SaaS分析.md` + `AI Agent替代SaaS分析.html`

3. **文件输出位置**:`/mnt/user-data/outputs/deepthink/`(逻辑上和 `output-templates/` 平级的报告输出位置)

4. **如果生成了 HTML**:运行 `output-templates/build-index.py` 重建索引页 `index.html`(扫描 outputs 目录的所有 .html 报告,生成卡片列表页)

5. 调用 `present_files` 把生成的文件呈现给用户

**如果用户选"不需要"**:流程直接结束,什么都不做。

## 关键规则速查

1. **不要硬套**:符合"拒绝判断"标准的问题,直接拒绝并解释,不要套方法论
2. **必须显式选择理由**:每选一个方法论,都要 1 句话说清"为什么这里用得上"
3. **必须 Checkpoint 1**:选完方法论必须停下来让用户确认,不要直接跑
4. **分歧不要调和**:方法论之间打架时,保留分歧,在综合里高亮
5. **质量自检不要跳**:每个方法论文件结尾都有"做得不到位的信号",跑完务必自查
6. **文件输出是用户选项,不是默认**:综合完成后必须问用户是否生成 md/html/两者/不需要,文件名遵循 ≤20 字中文总结规则,生成 html 后要重建 index.html
