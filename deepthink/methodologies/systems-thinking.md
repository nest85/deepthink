# 系统思维(Systems Thinking)

**一句话**:不孤立看单点,看结构——存量、流量、反馈环、延迟。系统的行为来自结构,不来自意志。

---

## 适用场景

- **理解类**:为什么这个现象持续/重复发生?
- **诊断类**:为什么解决了一个问题又冒出新的?
- **预测类**:这个系统短期 vs 长期行为会怎么不同?

## 不适用场景

- 纯个体决策(没有反馈环)
- 信息完全充分的简单计算题

## 互补方法论

- **+ 利益结构**:系统结构 + 利益结构 = 完整画像。利益结构常常是反馈环的驱动力
- **+ 二阶思维**:系统看结构,二阶看时间——结构 + 时间 = 全维度
- **+ 第一性原理**:先用第一性原理找出底层约束,再用系统思维看约束如何在结构里传导

## 冗余方法论

- 与二阶思维有重叠(都看动态),但侧重不同——可同选

## 执行步骤

### 1. 画出关键变量

列出系统里的核心变量(3-7 个)。变量是**可以增加或减少的量**。

> 例(系统:某城市的交通拥堵)
> 变量:车辆数、道路容量、公共交通使用率、出行需求、平均速度

### 2. 识别存量与流量

- **存量**:某个时间点的"余额"(车辆数、人口、银行存款)
- **流量**:单位时间的"流入流出"(新车注册数 - 报废数 = 净流入)

存量变化慢,流量变化快。**很多政策失败是因为只动流量没动存量**。

### 3. 找反馈环

变量之间的因果链条,如果**绕回到自己**,就是反馈环。

**正反馈(自我强化)**:A 增 → B 增 → A 更增
> 例:车多 → 平均速度低 → 公共交通也慢 → 更多人买车 → 车更多

**负反馈(自我抑制)**:A 增 → B 增 → A 减
> 例:车多 → 油价上涨 → 用车成本高 → 车减少

### 4. 识别延迟

反馈不是立即发生的。延迟越长,系统越容易**过冲**(决策时已经晚了)。

> 例:盖一条新路缓解拥堵——3 年后建成,但 3 年中需求已经长起来了,新路开通即拥堵(诱导需求)。

### 5. 找杠杆点

根据 Donella Meadows,系统改变的**杠杆点**从弱到强大致是:

| 弱 → 强 | 杠杆点 |
|---|---|
| 弱 | 调参数(税率 5% 改 6%) |
| ↓ | 改流量比率 |
| ↓ | 改存量结构 |
| ↓ | 改信息流(谁看到什么数据) |
| ↓ | 改激励规则 |
| ↓ | 改正反馈环的结构 |
| ↓ | 改系统目标 |
| 强 | 改系统的"思维范式" |

**结构改变 >> 参数调整**。

### 6. 推演系统行为

基于结构,推演**短期、中期、长期**会发生什么。注意:延迟会让短期假象掩盖长期趋势。

## 质量自检

- ❌ 没找到任何反馈环——可能只画了线性因果,不是系统
- ❌ 反馈环只有正反馈或只有负反馈——真实系统通常正负都有
- ❌ 杠杆点全是"调参数"型,没有"改结构"型——说明没看到深层
- ❌ 短期、中期、长期预测一样——说明没看到延迟效应
- ❌ 没找到任何反直觉发现——可能系统太简单或分析太浅

## Worked Example

**问题**:为什么某团队 always 在救火,搞不出长期规划?

### 关键变量
- 紧急任务数量
- 长期规划投入时间
- 团队疲劳度
- 历史欠债(技术债、流程债)
- 信任度(管理层对团队的信任)

### 存量与流量
- **存量**:历史欠债(累积的技术债、未做完的规划)、团队疲劳度
- **流量**:每周新增的紧急任务、每周还的债、每周新增的疲劳

### 反馈环

**正反馈环 1(救火螺旋)**:
紧急任务多 → 长期规划时间被挤压 → 没做规划 → 没识别风险 → 风险爆发为紧急任务 → 紧急任务更多

**正反馈环 2(疲劳螺旋)**:
紧急任务多 → 团队疲劳 → 出错率上升 → 出错变成紧急任务 → 更累

**负反馈环(本应存在但被压制)**:
还了债 → 紧急任务减少 → 有时间还更多债 → 但被正反馈淹没

### 关键延迟
- 规划→效果有 3-6 个月延迟
- 技术债→爆发可能数月或数年
- 管理层信任度恢复需要看到稳定输出,通常 6-12 个月

### 杠杆点
- 弱:开会催进度(调参数)
- 中:增加人手(调流量)
- 中强:设置"无紧急任务日"或"20% 还债时间"(改流量比例)
- 强:**彻底停止接新需求 N 周,只还债**(结构性改变,改变存量轨迹)
- 最强:改变激励——团队 KPI 从"完成多少任务"改为"系统稳定性 + 长期规划质量"(改激励规则)

### 系统行为预测
- 短期(3 个月):如果不结构性干预,救火只会越来越严重
- 中期(1 年):团队人员开始流失,知识进一步丢失,陷入恶性循环
- 长期(3 年):系统崩溃或被换团队/重写

### 反直觉发现
- "加人"通常没用——新人学习成本反而占用救火资源,短期更糟(Brooks's Law)
- "更努力工作"会让问题变严重——疲劳螺旋
- 真正的解法是反直觉的:**短期降产出 → 长期才能升产出**。但管理层往往不接受"暂时降产出"
